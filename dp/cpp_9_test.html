#include <QtTest>

SQL (structured query language - «структурированный язык запросов») - формальный непроцедурный язык программирования, применяемый для создания, модификации и управления данными в произвольной реляционной базе данных, управляемой соответствующей системой управления базами данных (СУБД). SQL основывается на исчислении кортежей.

SQLite - компактная встраиваемая реляционная база данных. Исходный код библиотеки передан в общественное достояние. В 2005 году проект получил награду Google-O’Reilly Open Source Awards.

Слово «встраиваемый» означает, что SQLite не использует парадигму клиент-сервер, то есть движок SQLite не является отдельно работающим процессом, с которым взаимодействует программа, а предоставляет библиотеку, с которой программа компонуется и движок становится составной частью программы. Таким образом, в качестве протокола обмена используются вызовы функций (API) библиотеки SQLite. Такой подход уменьшает накладные расходы, время отклика и упрощает программу. SQLite хранит всю базу данных (включая определения, таблицы, индексы и данные) в единственном стандартном файле на том компьютере, на котором исполняется программа. Простота реализации достигается за счёт того, что перед началом исполнения транзакции записи весь файл, хранящий базу данных, блокируется.

Несколько процессов или потоков могут одновременно без каких-либо проблем читать данные из одной базы. Запись в базу можно осуществить только в том случае, если никаких других запросов в данный момент не обслуживается; в противном случае попытка записи оканчивается неудачей, и в программу возвращается код ошибки. Другим вариантом развития событий является автоматическое повторение попыток записи в течение заданного интервала времени.

В комплекте поставки идёт также функциональная клиентская часть в виде исполняемого файла sqlite3, с помощью которого демонстрируется реализация функций основной библиотеки. Клиентская часть работает из командной строки, позволяет обращаться к файлу БД на основе типовых функций ОС.

Благодаря архитектуре движка возможно использовать SQLite как на встраиваемых системах, так и на выделенных машинах с гигабайтными массивами данных.

Использование: сама библиотека SQLite написана на C; существует большое количество привязок к другим языкам программирования, в том числе Delphi, C++, Java, C#, VB.NET, Python, Perl, PHP, Ruby, Haskell, Scheme, Smalltalk, Lua и Parser, а также ко многим другим. Полный список: http://www.sqlite.org/cvstrac/wiki?p=SqliteWrappers

Простота и удобство встраивания SQLite привели к тому, что библиотека используется в браузерах, музыкальных плеерах и многих других программах.

Язык SQL: SELECT, INSERT, UPDATE, DELETE

SQL: DDL + DML + DCL.

Data Definition Language (DDL) (язык описания данных) - семейство компьютерных языков, используемых в компьютерных программах для описания структуры баз данных.

Data Manipulation Language (DML) (язык управления/манипулирования данными) - это семейство компьютерных языков, используемых в компьютерных программах или пользователями баз данных для получения, вставки, удаления или изменения данных в базах данных.

Data Control Language (DCL) (управления БД) - подмножество языка управления базами данных SQL, предназначенное для осуществления административных операций, присваивающих или отменяющих право (привилегию) использовать базу данных, таблицы и другие объекты базы данных, а также выполнять те или иные операторы SQL.

  • GRANT — применяется для присвоения привилегии;
  • REVOKE — применяется для отмены привилегии.

SELECT

SELECT (выбрать) - оператор DML языка SQL, возвращающий набор данных (выборку) из базы данных, удовлетворяющих заданному условию.

В большинстве случаев, выборка осуществляется из одной или нескольких таблиц. В последнем случае говорят об операции слияния - JOIN. В тех СУБД, где реализованы представления (view) и хранимые процедуры (stored procedure), также возможно получение соответствующих наборов данных.

При формировании запроса SELECT пользователь описывает ожидаемый набор данных: его вид (набор столбцов) и его содержимое (критерий попадания записи в набор, группировка значений, порядок вывода записей и т. п.).

Запрос выполняется следующим образом (до оптимизации): сначала извлекаются все записи из таблицы, а затем для каждой записи набора проверяется её соответствие заданному критерию. Если осуществляется слияние из нескольких таблиц, то сначала составляется произведение таблиц, а уже затем из полученного набора отбираются требуемые записи.

Особую роль играет обработка NULL-значений, когда при слиянии, например, двух таблиц — главной (master) и подчинённой (detail) — имеются или отсутствуют соответствия между записями таблиц, участвующих в слиянии. Для решения этой задачи используются механизмы внутреннего (inner) и внешнего (outer) слияния.

Один и тот же набор данных может быть получен при выполнении различных запросов. Поиск оптимального плана выполнения данного запроса является задачей оптимизатора.

Соединение с базой данных. Выполнение инструкций SQL

Для работы с базами данных в Qt есть модуль QtSql. Чтобы его подключить, в файл проекта .pro добавляют строку QT += sql, а в исходный текст — #include <QtSql>. Основные классы модуля:

  • QSqlDatabase — соединение с базой данных;
  • QSqlQuery — выполнение инструкции SQL и обход результирующей выборки;
  • QSqlError — описание ошибки, которую сообщили драйвер или СУБД;
  • QSqlQueryModel, QSqlTableModel — модели для показа данных в таблице (см. ниже).

Порядок работы: подключиться к базе, создать таблицы, если их ещё нет, заполнить их и выполнять запросы. Инструкции SQL в примерах ниже записаны для SQLite и выполняются одна за другой над одной и той же базой.

Подключение к Базе Данных

Соединение создаёт статическая функция QSqlDatabase::addDatabase, которой передают имя драйвера: QSQLITE для SQLite, QMYSQL для MySQL, QPSQL для PostgreSQL, QODBC для источников данных ODBC. Если имя соединения не указано, создаётся соединение по умолчанию, и объекты QSqlQuery работают с ним.

Для SQLite имя базы данных — это имя файла, его задаёт функция setDatabaseName. Функция open() открывает базу и возвращает false, если это не удалось; причину сообщает lastError().text(). Если файла ещё нет, SQLite создаёт новую пустую базу. Серверной СУБД нужны ещё адрес сервера, имя пользователя и пароль: setHostName, setUserName, setPassword.

Код подключения к SQLite приведён в лекции «SQL (на примере sqlite), QtSql».

Создание схемы БД

Схема базы данных — это набор таблиц с их столбцами, типами и ограничениями. Таблицу создаёт инструкция DDL CREATE TABLE. Её текст передают в QSqlQuery::exec, который возвращает false при ошибке; каждую инструкцию выполняют отдельным вызовом exec.

CREATE TABLE IF NOT EXISTS student (
    id    INTEGER PRIMARY KEY AUTOINCREMENT,
    name  TEXT    NOT NULL,
    grade INTEGER
);

Слова IF NOT EXISTS позволяют выполнять инструкцию CREATE TABLE повторно: если таблица уже есть, инструкция ничего не делает. Это относится только к созданию таблицы: инструкции INSERT из следующего раздела при повторном запуске программы добавят те же записи ещё раз. Столбец id объявлен как INTEGER PRIMARY KEY AUTOINCREMENT: SQLite сама назначает каждой новой записи номер, больший всех прежних.

Добавление данных

Записи добавляет инструкция DML INSERT. Столбец id в ней не указан: его значение назначает СУБД, а узнать его после вставки можно функцией QSqlQuery::lastInsertId().

INSERT INTO student (name, grade) VALUES ('Иванов', 5);
INSERT INTO student (name, grade) VALUES ('Петров', 3);
INSERT INTO student (name, grade) VALUES ('Сидорова', 4);

Значения, введённые пользователем, не вписывают в текст запроса: кавычка в строке сломает инструкцию, а специально подобранная строка изменит её смысл (SQL-инъекция). Вместо этого запрос с параметрами готовят функцией prepare, значения параметров задают функцией bindValue и вызывают exec() без аргументов. Значения подставляет драйвер, экранировать их вручную не нужно. Вместо именованных параметров можно писать ? и передавать значения по порядку функцией addBindValue.

INSERT INTO student (name, grade) VALUES (:name, :grade);

Дальше считается, что этот запрос выполнен со значениями :name = 'Кузнецова' и :grade = 5.

Выполнение запроса и навигация по результирующей выборке

Инструкцию SELECT выполняют тем же exec. После выполнения объект QSqlQuery стоит перед первой записью выборки, поэтому сначала вызывают next(): эта функция переходит к следующей записи и возвращает false, когда записи кончились. Обычный обход выборки — цикл while (query.next()). Значение столбца текущей записи возвращает value(i) в виде QVariant (его переводят в нужный тип функциями toString(), toInt()). Столбцы нумеруются с нуля в том порядке, в котором они перечислены после SELECT; номер столбца по его имени даёт record().indexOf().

SELECT name, grade FROM student WHERE grade >= 4 ORDER BY name;

На данных из предыдущих разделов запрос вернёт три записи, и цикл пройдёт их в таком порядке:

value(0): name value(1): grade
Иванов 5
Кузнецова 5
Сидорова 4

Кроме next() есть previous(), first(), last() и seek(n) — переход к записи с номером n. Если выборку достаточно пройти один раз вперёд, до exec вызывают setForwardOnly(true): возвращаться назад тогда нельзя, зато, в зависимости от драйвера, пройденные записи не хранятся в памяти. Не все драйверы сообщают число записей выборки; в этом случае size() возвращает −1, поэтому выборку обходят циклом с next().

Вставка, изменение и удаление записей

Записи вставляет инструкция INSERT (см. «Добавление данных»), изменяет — UPDATE, удаляет — DELETE. Условие WHERE отбирает записи, к которым применяется инструкция; без него UPDATE и DELETE затрагивают все записи таблицы.

UPDATE student SET grade = grade + 1 WHERE name = 'Петров';
DELETE FROM student WHERE name = 'Сидорова';

Первая инструкция повышает оценку Петрова с 3 до 4, вторая удаляет запись Сидоровой. Сколько записей изменила инструкция, сообщает QSqlQuery::numRowsAffected(); здесь каждая инструкция затрагивает одну запись. Если условию WHERE не удовлетворяет ни одна запись, это не ошибка: exec вернёт true, а numRowsAffected() — 0. Значения, полученные от пользователя, и здесь передают через параметры, как в INSERT.

Транзакции

Транзакция — группа инструкций, которая выполняется целиком или не выполняется совсем. Пример — перевод денег со счёта на счёт: списание и зачисление — две инструкции UPDATE, и если программа остановится между ними, деньги спишутся, но не зачислятся. Транзакцию начинает BEGIN TRANSACTION; COMMIT фиксирует все её изменения, ROLLBACK отменяет их и возвращает базу в состояние до начала транзакции.

CREATE TABLE account (
    id      INTEGER PRIMARY KEY,
    owner   TEXT    NOT NULL,
    balance INTEGER NOT NULL CHECK (balance >= 0)
);
INSERT INTO account (id, owner, balance) VALUES (1, 'Иванов', 500);
INSERT INTO account (id, owner, balance) VALUES (2, 'Петров', 100);

BEGIN TRANSACTION;
UPDATE account SET balance = balance - 300 WHERE id = 1;
UPDATE account SET balance = balance + 300 WHERE id = 2;
COMMIT;

После перевода на первом счёте 200, на втором 400. Если бы на первом счёте было меньше 300, ограничение CHECK (balance >= 0) отклонило бы первую инструкцию UPDATE с ошибкой. Если второй UPDATE не изменил ни одной записи (счёта с таким номером нет), программа вместо COMMIT выполняет ROLLBACK, и списание с первого счёта отменяется.

В Qt транзакцией управляют функции QSqlDatabase: transaction(), commit() и rollback(); поддерживает ли драйвер транзакции, сообщает driver()->hasFeature(QSqlDriver::Transactions). В SQLite каждая инструкция вне явной транзакции выполняется как отдельная транзакция, поэтому много INSERT подряд быстрее выполнять внутри одной транзакции.

Использование классов-моделей SQL (модель запроса, модель таблицы). Отображение данных в таблице-представлении.

Чтобы показать данные в таблице на экране, выборку не обязательно обходить вручную. В Qt принята архитектура «модель — представление»: модель отдаёт данные, а представление (виджет QTableView) рисует их и само запрашивает у модели нужные ячейки. Модель связывают с представлением функцией setModel; одну модель можно показывать в нескольких представлениях сразу.

Модуль QtSql содержит готовые модели:

  • QSqlQueryModel (модель запроса) — результат произвольного SELECT, который задают функцией setQuery; данные доступны только для чтения;
  • QSqlTableModel (модель таблицы) — одна таблица с возможностью редактирования: имя таблицы задаёт setTable, данные загружает select(), условие отбора (часть WHERE без самого слова) и сортировку задают setFilter и setSort;
  • QSqlRelationalTableModel — модель таблицы, в которой столбец с внешним ключом показывает значение из связанной таблицы (функция setRelation).

Когда изменения из QSqlTableModel записываются в базу, определяет setEditStrategy: OnFieldChange — сразу после изменения ячейки, OnRowChange — при переходе к другой строке, OnManualSubmit — только по вызову submitAll(); revertAll() отменяет несохранённые изменения. Заголовки столбцов задаёт setHeaderData, иначе в заголовках выводятся имена полей.

Системы контроля версий, git. Юнит-тестирование. QtTest. Shell

Что такое система контроля версий и чем централизованные системы отличаются от распределённых, рассказано в лекции «Системы контроля версий». Git — распределённая система: у каждого разработчика полная копия репозитория вместе с историей. С git работают из командной оболочки (shell); основные команды:

  • git init — создать репозиторий в текущем каталоге, git clone — скопировать существующий;
  • git status и git diff — посмотреть, какие файлы и строки изменены;
  • git add — отметить изменения для следующего коммита, git commit — зафиксировать их;
  • git log — история коммитов;
  • git branch имя — создать ветку, git checkout имя — перейти на неё, git merge имя — влить её в текущую ветку;
  • git pull и git push — получить изменения из удалённого репозитория и отправить в него свои.

Модульные тесты и разработка через тестирование разобраны на примере JUnit в лекции «Пример модульных тестов на Java». В QtTest (подключение описано в начале этой страницы) тестовый класс наследуется от QObject и содержит макрос Q_OBJECT; каждый тест — это закрытый слот (private slot), а проверки записывают макросами QVERIFY(условие) и QCOMPARE(фактическое, ожидаемое). Слоты initTestCase() и cleanupTestCase() выполняются до и после всех тестов, init() и cleanup() — до и после каждого теста.

QTest::qExec возвращает 0, если все тесты прошли, и ненулевое значение, если есть ошибки. Чтобы результат тестов увидела командная оболочка, функция main должна вернуть именно это значение — так делает макрос QTEST_MAIN: он создаёт объект теста и возвращает результат QTest::qExec. В примере в начале этой страницы main возвращает 0 при любом исходе тестов, поэтому для такой проверки две последние строки её тела надо заменить одной: return QTest::qExec(new MyClassTest, argc, argv);. Оболочка выполняет команду после && только тогда, когда предыдущая завершилась с кодом 0, поэтому в строке вида ./tests && git commit коммит выполнится, только если тесты прошли. Так выполняется совет из лекции о контроле версий: фиксировать изменения после того, как модули проходят тесты.
