SQL, SQLite

SQL (structured query language - «структурированный язык запросов») - формальный непроцедурный язык программирования, применяемый для создания, модификации и управления данными в произвольной реляционной базе данных, управляемой соответствующей системой управления базами данных (СУБД). SQL основывается на исчислении кортежей.

SQLite - компактная встраиваемая реляционная база данных. Исходный код библиотеки передан в общественное достояние. В 2005 году проект получил награду Google-O’Reilly Open Source Awards.

Слово «встраиваемый» означает, что SQLite не использует парадигму клиент-сервер, то есть движок SQLite не является отдельно работающим процессом, с которым взаимодействует программа, а предоставляет библиотеку, с которой программа компонуется и движок становится составной частью программы. Таким образом, в качестве протокола обмена используются вызовы функций (API) библиотеки SQLite. Такой подход уменьшает накладные расходы, время отклика и упрощает программу. SQLite хранит всю базу данных (включая определения, таблицы, индексы и данные) в единственном стандартном файле на том компьютере, на котором исполняется программа. Простота реализации достигается за счёт того, что перед началом исполнения транзакции записи весь файл, хранящий базу данных, блокируется.

Несколько процессов или потоков могут одновременно без каких-либо проблем читать данные из одной базы. Запись в базу можно осуществить только в том случае, если никаких других запросов в данный момент не обслуживается; в противном случае попытка записи оканчивается неудачей, и в программу возвращается код ошибки. Другим вариантом развития событий является автоматическое повторение попыток записи в течение заданного интервала времени.

В комплекте поставки идёт также функциональная клиентская часть в виде исполняемого файла sqlite3, с помощью которого демонстрируется реализация функций основной библиотеки. Клиентская часть работает из командной строки, позволяет обращаться к файлу БД на основе типовых функций ОС.

Благодаря архитектуре движка возможно использовать SQLite как на встраиваемых системах, так и на выделенных машинах с гигабайтными массивами данных.

Использование: сама библиотека SQLite написана на C; существует большое количество привязок к другим языкам программирования, в том числе Delphi, C++, Java, C#, VB.NET, Python, Perl, PHP, Ruby, Haskell, Scheme, Smalltalk, Lua и Parser, а также ко многим другим. Полный список: http://www.sqlite.org/cvstrac/wiki?p=SqliteWrappers

Простота и удобство встраивания SQLite привели к тому, что библиотека используется в браузерах, музыкальных плеерах и многих других программах.

Язык SQL: SELECT, INSERT, UPDATE, DELETE

SQL: DDL + DML + DCL.

Data Definition Language (DDL) (язык описания данных) - семейство компьютерных языков, используемых в компьютерных программах для описания структуры баз данных.

Data Manipulation Language (DML) (язык управления/манипулирования данными) - это семейство компьютерных языков, используемых в компьютерных программах или пользователями баз данных для получения, вставки, удаления или изменения данных в базах данных.

Data Control Language (DCL) (управления БД) - подмножество языка управления базами данных SQL, предназначенное для осуществления административных операций, присваивающих или отменяющих право (привилегию) использовать базу данных, таблицы и другие объекты базы данных, а также выполнять те или иные операторы SQL.

  • GRANT — применяется для присвоения привилегии;
  • REVOKE — применяется для отмены привилегии.

SELECT

SELECT (выбрать) - оператор DML языка SQL, возвращающий набор данных (выборку) из базы данных, удовлетворяющих заданному условию.

В большинстве случаев, выборка осуществляется из одной или нескольких таблиц. В последнем случае говорят об операции слияния - JOIN. В тех СУБД, где реализованы представления (view) и хранимые процедуры (stored procedure), также возможно получение соответствующих наборов данных.

При формировании запроса SELECT пользователь описывает ожидаемый набор данных: его вид (набор столбцов) и его содержимое (критерий попадания записи в набор, группировка значений, порядок вывода записей и т. п.).

Запрос выполняется следующим образом (до оптимизации): сначала извлекаются все записи из таблицы, а затем для каждой записи набора проверяется её соответствие заданному критерию. Если осуществляется слияние из нескольких таблиц, то сначала составляется произведение таблиц, а уже затем из полученного набора отбираются требуемые записи.

Особую роль играет обработка NULL-значений, когда при слиянии, например, двух таблиц — главной (master) и подчинённой (detail) — имеются или отсутствуют соответствия между записями таблиц, участвующих в слиянии. Для решения этой задачи используются механизмы внутреннего (inner) и внешнего (outer) слияния.

Один и тот же набор данных может быть получен при выполнении различных запросов. Поиск оптимального плана выполнения данного запроса является задачей оптимизатора.

Соединение с базой данных. Выполнение инструкций SQL

Классы для работы с базами данных собраны в модуле QtSql. Чтобы подключить его, в файл проекта .pro добавляют строку QT += sql, а в исходный текст — заголовочный файл класса, например #include <QSqlQuery>. Основные классы модуля:

  • QSqlDatabase — соединение с базой данных;
  • QSqlQuery — выполнение инструкции SQL и перебор записей результата;
  • QSqlError — описание ошибки;
  • QSqlQueryModel, QSqlTableModel — модели для показа данных в виджетах (см. ниже).

Порядок работы: открыть соединение, выполнить инструкции SQL, обработать результат. В примерах этого раздела используется таблица учеников student в базе SQLite.

Подключение к Базе Данных

Соединение с базой данных представляет объект QSqlDatabase. Его создаёт статический метод QSqlDatabase::addDatabase(), которому передают имя драйвера: "QSQLITE" для SQLite, "QMYSQL" для MySQL, "QPSQL" для PostgreSQL, "QODBC" для источников ODBC. Список драйверов, доступных программе, возвращает QSqlDatabase::drivers().

Для SQLite имя базы данных, которое задаёт метод setDatabaseName(), — это имя файла; если файла нет, SQLite создаёт его при открытии. Специальное имя ":memory:" открывает базу в оперативной памяти: она исчезает при закрытии соединения. Для серверных СУБД (MySQL, PostgreSQL) кроме имени базы задают адрес сервера и учётную запись: setHostName(), setPort(), setUserName(), setPassword().

Соединение открывает метод open(), он возвращает true при успехе. При неудаче причину сообщает lastError(): объект QSqlError, текст ошибки возвращает его метод text(). Соединение, созданное без имени, становится соединением по умолчанию: его используют объекты QSqlQuery, которым соединение не передано явно.

Создание схемы БД

Схема базы данных — это её таблицы, их столбцы и ограничения. Схему создают инструкциями DDL, прежде всего CREATE TABLE. В Qt такую инструкцию, как и любую другую, выполняет метод QSqlQuery::exec(): он возвращает true, если инструкция выполнена, а при ошибке её причину сообщает lastError().

Таблица учеников:

CREATE TABLE IF NOT EXISTS student (
    id    INTEGER PRIMARY KEY AUTOINCREMENT,
    name  TEXT NOT NULL,
    grade INTEGER
);

Слова IF NOT EXISTS позволяют выполнять инструкцию CREATE TABLE повторно: если таблица уже есть в файле базы, инструкция ничего не делает и ошибкой не считается. Это относится только к созданию таблицы: инструкции INSERT из следующего раздела при повторном запуске программы добавят те же записи ещё раз. Столбец INTEGER PRIMARY KEY SQLite нумерует сама: если при вставке значение id не указано, оно назначается автоматически, а AUTOINCREMENT запрещает повторно выдавать номера удалённых записей. NOT NULL не даёт добавить ученика без имени.

Добавление данных

Записи добавляет инструкция INSERT. В скобках после имени таблицы перечисляют столбцы, после VALUES — их значения в том же порядке. Столбец id не указан и получает номер автоматически. Строки в SQL заключают в одинарные кавычки.

INSERT INTO student (name, grade) VALUES ('Иванов', 5);
INSERT INTO student (name, grade) VALUES ('Петров', 3);
INSERT INTO student (name, grade) VALUES ('Сидорова', 4);

Для SQLite строка запроса может содержать только одну инструкцию, поэтому три вставки — это три вызова exec(). Номер только что добавленной записи возвращает QSqlQuery::lastInsertId(); при первом запуске в пустую таблицу записи получат номера 1, 2 и 3.

Значения, которые вводит пользователь, нельзя вклеивать в текст запроса: кавычка в фамилии сломает запрос, а специально подобранная строка изменит его смысл (SQL-инъекция). Вместо этого запрос с заполнителями INSERT INTO student (name, grade) VALUES (:name, :grade) передают методу prepare(), значения задают методом bindValue() (имя заполнителя и значение), для позиционных заполнителей ? — методом addBindValue(), после чего вызывают exec() без аргументов. Подготовленный запрос можно выполнить много раз с разными значениями.

Выполнение запроса и навигация по результирующей выборке

Выборку возвращает инструкция SELECT. Ученики с оценкой не ниже 4 в алфавитном порядке:

SELECT id, name, grade FROM student WHERE grade >= 4 ORDER BY name;
id name grade
1 Иванов 5
3 Сидорова 4

После успешного exec() запрос становится активным (isActive() возвращает true) и стоит перед первой записью выборки. Метод next() переходит к следующей записи и возвращает false, когда записи кончились, поэтому выборку перебирают в цикле, пока next() возвращает true. Значение поля текущей записи возвращает value() по номеру столбца в списке SELECT (с нуля: 0 — id, 1 — name, 2 — grade); номер столбца по его имени даёт record().indexOf(). Результат имеет тип QVariant, в нужный тип его переводят методы toInt(), toString(), toDouble().

Кроме next(), по выборке перемещаются методы previous(), first(), last() и seek() (переход к записи с заданным номером, нумерация с нуля). Если нужен только проход вперёд, вызов setForwardOnly(true) до exec() может уменьшить расход памяти: пройденные записи не нужно хранить. Число записей выборки возвращает size(), но драйвер SQLite его не сообщает и size() возвращает -1; записи считают при переборе или запросом SELECT COUNT(*) FROM student.

Вставка, изменение и удаление записей

Инструкции DML INSERT, UPDATE и DELETE выборки не возвращают. Их, как и CREATE TABLE, выполняет QSqlQuery::exec(), а сколько записей затронула инструкция, сообщает numRowsAffected().

INSERT INTO student (name, grade) VALUES ('Кузнецова', 2);
UPDATE student SET grade = 4 WHERE name = 'Петров';
DELETE FROM student WHERE grade < 3;

Здесь добавлена ученица Кузнецова, Петрову исправлена оценка, затем удалены все записи с оценкой ниже 3: в данном случае одна, Кузнецовой. Каждая из трёх инструкций затрагивает одну запись. В таблице остаются Иванов (5), Петров (4) и Сидорова (4).

UPDATE и DELETE без WHERE действуют на все записи таблицы: DELETE FROM student удаляет всех учеников. Поэтому условие проверяют особенно внимательно, а конкретную запись выбирают по первичному ключу: условие WHERE id = 2 затрагивает ровно одну запись, а условие по фамилии — всех однофамильцев.

Транзакции

Транзакция — группа инструкций, которая выполняется как одно целое: сохраняются либо все её изменения, либо ни одно. Пример — перевод денег между счетами: списание с одного счёта без зачисления на другой оставит базу в неверном состоянии.

CREATE TABLE account (id INTEGER PRIMARY KEY, balance INTEGER NOT NULL);
INSERT INTO account (id, balance) VALUES (1, 500);
INSERT INTO account (id, balance) VALUES (2, 100);

BEGIN TRANSACTION;
UPDATE account SET balance = balance - 100 WHERE id = 1;
UPDATE account SET balance = balance + 100 WHERE id = 2;
COMMIT;

После COMMIT на счетах 400 и 200. Если бы после первого UPDATE произошла ошибка, программа выполнила бы ROLLBACK: изменения, сделанные после BEGIN, отменяются, и на счетах остаются 500 и 100.

В Qt транзакцией управляют методы соединения: QSqlDatabase::transaction() начинает её, commit() подтверждает, rollback() отменяет; все три возвращают true при успехе. Поддерживает ли драйвер транзакции, сообщает метод драйвера hasFeature() с аргументом QSqlDriver::Transactions. Драйвер SQLite транзакции поддерживает.

Вне явной транзакции SQLite выполняет каждую инструкцию как отдельную транзакцию, а завершение транзакции требует дождаться записи на диск. Поэтому много вставок подряд выгодно объединять в одну транзакцию: запись на диск при подтверждении происходит один раз, а не после каждой инструкции.

Использование классов-моделей SQL (модель запроса, модель таблицы). Отображение данных в таблице-представлении.

Для показа данных в виджетах QtSql предоставляет модели архитектуры «модель — представление». Модель берёт данные из базы, представление (виджет) их отображает; один и тот же класс представления работает с любой моделью.

  • QSqlQueryModel — модель запроса: результат произвольного SELECT, который задают методом setQuery(), только для чтения. Запрос может соединять несколько таблиц.
  • QSqlTableModel — модель таблицы: одна таблица, которую можно редактировать. Таблицу задаёт setTable(), условие отбора — setFilter() (текст условия WHERE без самого слова WHERE, например grade >= 4), порядок — setSort(); данные загружает select().
  • QSqlRelationalTableModel — модель таблицы, в которой вместо значения внешнего ключа показывается поле связанной таблицы (например, название класса вместо его номера).

Таблицу на экране показывает виджет QTableView: модель передают ему методом setModel(). Заголовки столбцов по умолчанию совпадают с именами полей, понятные пользователю названия задаёт метод модели setHeaderData().

Когда изменения из представления попадают в базу, определяет стратегия, которую задаёт метод setEditStrategy() модели таблицы: QSqlTableModel::OnFieldChange — сразу после изменения поля, OnRowChange — при переходе на другую строку, OnManualSubmit — только по вызову submitAll(). Метод revertAll() отменяет несохранённые изменения.

Системы контроля версий, git. Юнит-тестирование. QtTest. Shell

Система контроля версий хранит историю изменений исходного кода: к любой сохранённой версии можно вернуться, можно узнать, кто и когда внёс изменение, и объединить работу нескольких разработчиков. Основные понятия и виды таких систем — на странице «Системы контроля версий».

git — распределённая система контроля версий: у каждого разработчика полная копия репозитория с историей. Основные команды:

  • git init — создать репозиторий в текущем каталоге;
  • git clone — получить копию существующего репозитория;
  • git status — показать изменённые и новые файлы;
  • git add — отметить изменения файла для следующей фиксации;
  • git commit -m "сообщение" — зафиксировать отмеченные изменения в локальном репозитории;
  • git log — показать историю фиксаций;
  • git pull — получить изменения из удалённого репозитория и влить их в текущую ветку (если ветки разошлись, без настройки Git останавливается с ошибкой и требует указать --no-rebase для слияния или --rebase для перебазирования);
  • git push — отправить свои фиксации в удалённый репозиторий.

Юнит-тест (модульный тест) проверяет отдельную функцию или класс независимо от остальной программы. В Qt для этого есть библиотека QtTest: тестовый класс наследуют от QObject, каждый его закрытый слот — отдельный тест (кроме служебных слотов, например initTestCase() и cleanupTestCase()), а проверки записывают макросами QVERIFY (условие истинно) и QCOMPARE (значения равны). Подключение библиотеки — на странице «QtTest».

Shell — командная оболочка (например, bash в Linux, cmd или PowerShell в Windows). Из неё запускают git, сборку проекта и тесты, а повторяющиеся последовательности команд записывают в сценарии.
