SQL (на примере sqlite), QtSql

SQL (structured query language - «структурированный язык запросов») - формальный непроцедурный язык программирования, применяемый для создания, модификации и управления данными в произвольной реляционной базе данных, управляемой соответствующей системой управления базами данных (СУБД). SQL основывается на исчислении кортежей.

SQLite - компактная встраиваемая реляционная база данных. Исходный код библиотеки передан в общественное достояние. В 2005 году проект получил награду Google-O’Reilly Open Source Awards.

Слово «встраиваемый» означает, что SQLite не использует парадигму клиент-сервер, то есть движок SQLite не является отдельно работающим процессом, с которым взаимодействует программа, а предоставляет библиотеку, с которой программа компонуется и движок становится составной частью программы. Таким образом, в качестве протокола обмена используются вызовы функций (API) библиотеки SQLite. Такой подход уменьшает накладные расходы, время отклика и упрощает программу. SQLite хранит всю базу данных (включая определения, таблицы, индексы и данные) в единственном стандартном файле на том компьютере, на котором исполняется программа. Простота реализации достигается за счёт того, что перед началом исполнения транзакции записи весь файл, хранящий базу данных, блокируется.

Несколько процессов или потоков могут одновременно без каких-либо проблем читать данные из одной базы. Запись в базу можно осуществить только в том случае, если никаких других запросов в данный момент не обслуживается; в противном случае попытка записи оканчивается неудачей, и в программу возвращается код ошибки. Другим вариантом развития событий является автоматическое повторение попыток записи в течение заданного интервала времени.

В комплекте поставки идёт также функциональная клиентская часть в виде исполняемого файла sqlite3, с помощью которого демонстрируется реализация функций основной библиотеки. Клиентская часть работает из командной строки, позволяет обращаться к файлу БД на основе типовых функций ОС.

Благодаря архитектуре движка возможно использовать SQLite как на встраиваемых системах, так и на выделенных машинах с гигабайтными массивами данных.

Использование: сама библиотека SQLite написана на C; существует большое количество привязок к другим языкам программирования, в том числе Delphi, C++, Java, C#, VB.NET, Python, Perl, PHP, Ruby, Haskell, Scheme, Smalltalk, Lua и Parser, а также ко многим другим. Полный список: http://www.sqlite.org/cvstrac/wiki?p=SqliteWrappers

Простота и удобство встраивания SQLite привели к тому, что библиотека используется в браузерах, музыкальных плеерах и многих других программах.

Язык SQL: SELECT, INSERT, UPDATE, DELETE

SQL: DDL + DML + DCL.

Data Definition Language (DDL) (язык описания данных) - семейство компьютерных языков, используемых в компьютерных программах для описания структуры баз данных.

Data Manipulation Language (DML) (язык управления/манипулирования данными) - это семейство компьютерных языков, используемых в компьютерных программах или пользователями баз данных для получения, вставки, удаления или изменения данных в базах данных.

Data Control Language (DCL) (управления БД) - подмножество языка управления базами данных SQL, предназначенное для осуществления административных операций, присваивающих или отменяющих право (привилегию) использовать базу данных, таблицы и другие объекты базы данных, а также выполнять те или иные операторы SQL.

  • GRANT — применяется для присвоения привилегии;
  • REVOKE — применяется для отмены привилегии.

SELECT

SELECT (выбрать) - оператор DML языка SQL, возвращающий набор данных (выборку) из базы данных, удовлетворяющих заданному условию.

В большинстве случаев, выборка осуществляется из одной или нескольких таблиц. В последнем случае говорят об операции слияния - JOIN. В тех СУБД, где реализованы представления (view) и хранимые процедуры (stored procedure), также возможно получение соответствующих наборов данных.

При формировании запроса SELECT пользователь описывает ожидаемый набор данных: его вид (набор столбцов) и его содержимое (критерий попадания записи в набор, группировка значений, порядок вывода записей и т. п.).

Запрос выполняется следующим образом (до оптимизации): сначала извлекаются все записи из таблицы, а затем для каждой записи набора проверяется её соответствие заданному критерию. Если осуществляется слияние из нескольких таблиц, то сначала составляется произведение таблиц, а уже затем из полученного набора отбираются требуемые записи.

Особую роль играет обработка NULL-значений, когда при слиянии, например, двух таблиц — главной (master) и подчинённой (detail) — имеются или отсутствуют соответствия между записями таблиц, участвующих в слиянии. Для решения этой задачи используются механизмы внутреннего (inner) и внешнего (outer) слияния.

Один и тот же набор данных может быть получен при выполнении различных запросов. Поиск оптимального плана выполнения данного запроса является задачей оптимизатора.

JOIN

JOIN (INNER JOIN) - соединяем записи из двух таблиц, в конечной выборке будут только строки, когда запись есть и в левой таблице и в правой.

Соединение с базой данных. Выполнение инструкций SQL

Для работы с базами данных в Qt служит модуль QtSql. Чтобы подключить его к программе, в файл проекта .pro добавляют строку QT += sql. Основные классы модуля:

  • QSqlDatabase — соединение с базой данных;
  • QSqlQuery — выполнение инструкции SQL и перемещение по её результату;
  • QSqlError — описание ошибки; его возвращает метод lastError() соединения или запроса.

Ниже по шагам разобрана работа с базой SQLite: подключение, создание таблицы, добавление данных и выборка. Инструкции SQL приведены в том виде, в каком их выполняет SQLite; их можно проверить и в клиенте sqlite3.

Подключение к Базе Данных

Соединение создаёт статический метод QSqlDatabase::addDatabase(). Его первый аргумент — имя драйвера: QSQLITE для SQLite, QMYSQL для MySQL, QPSQL для PostgreSQL. Второй, необязательный, аргумент — имя соединения. Если его не указать, создаётся соединение по умолчанию: им пользуются все объекты QSqlQuery, которым соединение не передано явно.

Затем задают параметры соединения. Для SQLite достаточно имени базы данных, то есть имени файла (метод setDatabaseName()). Если файла нет, он будет создан при открытии. Имя :memory: означает базу в оперативной памяти: она исчезает, когда соединение закрывается. Серверным СУБД нужны также адрес сервера, имя пользователя и пароль: методы setHostName(), setUserName() и setPassword().

Метод open() открывает соединение и возвращает true при успехе. Результат нужно проверять: если файл недоступен или сервер не отвечает, open() вернёт false, а причину сообщит lastError().text().

Создание схемы БД

Схема базы данных — набор таблиц с их столбцами, типами и ограничениями. Её создают инструкциями DDL, прежде всего CREATE TABLE. В Qt текст инструкции передают методу exec() объекта QSqlQuery. Он возвращает false, если инструкция не выполнена, и тогда текст ошибки даёт lastError().

Таблица учеников, на которой построены примеры ниже:

CREATE TABLE IF NOT EXISTS students (
    id    INTEGER PRIMARY KEY,
    name  TEXT NOT NULL,
    grade INTEGER NOT NULL
);
  • IF NOT EXISTS — не создавать таблицу, если она уже есть и не выдавать ошибку: инструкцию можно выполнять повторно с тем же файлом базы данных;
  • INTEGER PRIMARY KEY — первичный ключ: значения столбца id не повторяются, и SQLite сам назначает значение, если при вставке оно не указано;
  • NOT NULL — у каждой записи в этом столбце должно быть значение.

Добавление данных

Записи добавляет инструкция INSERT. Столбцы перечисляют явно, а id не указывают: SQLite назначит записям номера 1, 2 и 3. Примеры ниже рассчитаны на первый запуск с пустой базой: при повторном запуске эти инструкции добавят записи ещё раз, и номера записей, а с ними и результаты примеров, будут другими.

INSERT INTO students (name, grade) VALUES ('Иванов', 9);
INSERT INTO students (name, grade) VALUES ('Петрова', 10);
INSERT INTO students (name, grade) VALUES ('Сидоров', 9);

Строковые значения в SQL заключают в одинарные кавычки. Каждую инструкцию передают в exec() отдельным вызовом.

Значения, полученные от пользователя, нельзя вклеивать в текст запроса: кавычка внутри строки (например, в фамилии О'Брайен) сделает запрос синтаксически неверным, а специально подобранная строка изменит его смысл. Такая атака называется SQL-инъекцией. Для внешних значений служат параметры запроса, см. раздел «Вставка, изменение и удаление записей».

Выполнение запроса и навигация по результирующей выборке

Запрос SELECT выполняется тем же методом exec(), а его результат, выборку, объект QSqlQuery обходит как курсор. Сразу после выполнения курсор стоит перед первой записью. Метод next() переходит к следующей записи и возвращает false, когда записи закончились, поэтому выборку читают в цикле, который вызывает next(), пока тот возвращает true.

SELECT id, name, grade FROM students WHERE grade = 9 ORDER BY name;

На данных из предыдущего раздела запрос вернёт две записи:

idnamegrade
1Иванов9
3Сидоров9

Значение столбца текущей записи возвращает метод value(). Его аргумент — номер столбца в списке SELECT, считая с нуля: здесь value(0) — номер записи, value(1) — фамилия. Результат имеет тип QVariant; к нужному типу его приводят методы toInt(), toString() и другие. Столбцы лучше перечислять в SELECT явно, а не писать SELECT *: тогда номер столбца не зависит от порядка столбцов в таблице.

По выборке можно перемещаться и в другом порядке: previous() — к предыдущей записи, first() и last() — к первой и последней, seek(n) — к записи с номером n (тоже считая с нуля). Это верно, если запрос не переведён в режим setForwardOnly(true): в этом режиме назад двигаться нельзя, и previous() возвращает false.

Вставка, изменение и удаление записей

Инструкции INSERT, UPDATE и DELETE выполняются тем же методом exec(), но выборки не возвращают. Число затронутых записей сообщает метод numRowsAffected(), а ключ последней добавленной записи — lastInsertId() (если драйвер это поддерживает; драйвер SQLite поддерживает).

Внешние значения передают через параметры. В тексте запроса вместо значений стоят метки: именованные (:name) или позиционные (?). Текст передают методу prepare(), значения подставляют методом bindValue() (по имени метки) или addBindValue() (по порядку меток), а затем вызывают exec() без аргументов. Значения подставляет драйвер, поэтому кавычки в них не меняют смысла запроса. Один подготовленный запрос можно выполнить много раз с разными значениями.

INSERT INTO students (name, grade) VALUES (:name, :grade);

Если подставить :name = 'Кузнецова' и :grade = 11, в таблице появится четвёртая запись, и lastInsertId() вернёт 4.

UPDATE изменяет значения столбцов у записей, удовлетворяющих условию WHERE; DELETE удаляет такие записи.

UPDATE students SET grade = grade + 1 WHERE grade = 9;
DELETE FROM students WHERE name = 'Сидоров';

Здесь UPDATE переводит Иванова и Сидорова в 10-й класс (numRowsAffected() вернёт 2), а DELETE удаляет одну запись. Без WHERE обе инструкции действуют на все записи таблицы.

Транзакции

Транзакция — группа инструкций, которая выполняется целиком или не выполняется совсем. Её начинает инструкция BEGIN TRANSACTION, фиксирует COMMIT, отменяет ROLLBACK: после отката база возвращается в состояние, в котором была до начала транзакции.

Пример: выпускников (grade = 11) переносят в таблицу graduates и удаляют из students. Если выполнится только одна из двух инструкций, ученик либо окажется в обеих таблицах, либо не окажется ни в одной; транзакция исключает оба случая.

CREATE TABLE IF NOT EXISTS graduates (
    id   INTEGER PRIMARY KEY,
    name TEXT NOT NULL
);

BEGIN TRANSACTION;
INSERT INTO graduates (id, name) SELECT id, name FROM students WHERE grade = 11;
DELETE FROM students WHERE grade = 11;
COMMIT;

На данных из предыдущего раздела в graduates попадёт запись Кузнецовой, а в students останутся Иванов и Петрова. Если вместо COMMIT выполнить ROLLBACK, обе таблицы останутся такими, какими были до BEGIN.

В Qt транзакцией управляют методы соединения QSqlDatabase: transaction() начинает её, commit() фиксирует, rollback() откатывает; каждый возвращает false при неудаче. Поддерживает ли драйвер транзакции, проверяют методом hasFeature() драйвера (его возвращает QSqlDatabase::driver()) с аргументом QSqlDriver::Transactions.

Вне явной транзакции SQLite выполняет каждую инструкцию как отдельную транзакцию и фиксирует её изменения в файле. Поэтому много INSERT подряд выполняются заметно быстрее, если объединить их в одну транзакцию.

Использование классов-моделей SQL (модель запроса, модель таблицы). Отображение данных в таблице-представлении.

Кроме QSqlQuery, в QtSql есть модели — классы архитектуры «модель/представление» (model/view), которые предоставляют данные из базы в виде таблицы строк и столбцов. Модель отвечает за данные, представление — за их показ на экране; одну модель можно показать в нескольких представлениях сразу.

  • QSqlQueryModel — модель запроса, только для чтения. Метод setQuery() получает текст SELECT, и модель содержит его результат. Подходит для показа любых выборок, в том числе из нескольких таблиц (JOIN).
  • QSqlTableModel — модель таблицы: чтение и изменение одной таблицы. Таблицу задаёт setTable(), условие отбора — setFilter() (текст условия WHERE без слова WHERE), порядок — setSort(); данные загружает select(). Изменения, сделанные через модель, она сама записывает в базу инструкциями UPDATE, INSERT и DELETE.
  • QSqlRelationalTableModel — модель таблицы с внешними ключами: вместо ключа записи из другой таблицы показывает значение выбранного столбца этой записи (например, название вместо числового идентификатора).

Когда изменения из QSqlTableModel попадают в базу, задаёт метод setEditStrategy():

  • OnFieldChange — сразу после изменения поля;
  • OnRowChange (по умолчанию) — когда пользователь переходит к другой строке;
  • OnManualSubmit — только при вызове submitAll(); revertAll() отменяет ещё не записанные изменения.

Отображение данных в таблице-представлении. Класс QTableView показывает модель в виде таблицы на экране; модель передают ему методом setModel(). Заголовками столбцов служат имена полей, другой текст задают методом модели setHeaderData(). Если модель редактируемая (QSqlTableModel), значения можно изменять прямо в ячейках таблицы, и в базу они попадут согласно выбранной стратегии редактирования.
